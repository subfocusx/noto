# Дизайн-система Noto

Документ описывает визуальный язык приложения: токены, темы, типографику,
иконки, отступы и правила, по которым пишется интерфейс — включая интерфейс
плагинов.

Источник истины — файл `frontend/src/styles/tokens.css`. Всё остальное
(компоненты, плагины) читает только семантические переменные.

---

## 1. Слои стилей

```
frontend/src/styles/
├── tokens.css      токены, темы, шкалы, motion — единственный источник цвета
├── base.css        reset, типографика, фокус, скроллбары, reduced-motion
├── layout.css      оболочка приложения, шапка, сайдбар, рабочая область, адаптив
├── rail.css        рельса разделов и колонка разделов (фаза 10)
├── tabs.css        полоса открытых вкладок (фаза 12)
├── tags.css        полоса тегов заметки (фаза 12)
├── components.css  кнопки, поля, дерево, диалоги, поиск, настройки
├── palette.css     модальное окно палитры команд (фаза 11)
├── calendar.css    сетка месяца раздела календаря (фаза 11)
├── notifications.css список уведомлений (фаза 11)
├── favorites.css   список избранного (фаза 12)
├── find.css        окно поиска и фильтров (фаза 13)
├── markdown.css    типографика предпросмотра
└── plugin.css      точки расширения плагинов
```

Правило: цвет, размер и радиус **никогда** не пишутся в правиле компонента.
Если нужен новый оттенок — сначала появляется токен.

## 2. Токены

### 2.1. Поверхности

| Токен | Назначение |
|---|---|
| `--bg-app` | фон рабочей области (редактор и предпросмотр) |
| `--bg-sidebar` | фон панели заметок |
| `--bg-surface` | фон шапки, подвала, карточек, панелей плагинов |
| `--bg-elevated` | фон диалогов, палитры, контекстного меню |
| `--bg-inset` | фон полей ввода, выпадающих списков, блоков кода |
| `--bg-hover` | подсветка при наведении |
| `--bg-active` | подсветка при нажатии |
| `--bg-selected` | выбранный элемент (заметка в дереве, строка палитры) |

### 2.2. Текст

| Токен | Назначение |
|---|---|
| `--fg` | основной текст |
| `--fg-secondary` | второстепенный текст (имена папок, подписи) |
| `--fg-muted` | приглушённый текст (пути, подсказки, время) |
| `--fg-on-accent` | текст на акцентной заливке |

Контраст основного текста к фону — не ниже 4.5:1 в обеих темах.

### 2.3. Границы, акцент, семантика

`--border`, `--border-strong`, `--divider`; `--accent`, `--accent-hover`,
`--accent-active`, `--accent-subtle`, `--accent-fg`; `--success`,
`--warning`, `--danger`, `--info` и их `-subtle`-варианты.

### 2.4. Шкала отступов и размеров

| Токен | Значение | Где применяется |
|---|---|---|
| `--space-1` … `--space-8` | 4, 8, 12, 16, 24, 32, 40, 56 px | отступы внутри блоков |
| `--radius-sm/md/lg/xl` | 2, 4, 8, 12 px | поля, кнопки, карточки, диалоги |
| `--radius-pill` | 4 px | «таблетки» запрещены: пилюля = 4 px |
| `--control-sm/md/lg` | 28, 32, 40 px | кнопки и поля по назначению |
| `--touch-target` | 44 px | минимальная цель нажатия на сенсорном экране |
| `--row-height` | 32 px | строка дерева и строка навигации |
| `--header-height` | 40 px | шапка каждой колонки (рельса, колонка, вкладки, outline) |
| `--tab-height` | 40 px | полоса вкладок редактора (это шапка рабочей области) |
| `--rail-width` | 44 px | рельса разделов |
| `--footer-height` | 24 px | строка состояния |
| `--sidebar-width` | 240 px | левая колонка |
| `--sidebar-width-min` / `--sidebar-width-max` | 200 px / 480 px | границы ресайза левой колонки |
| `--panel-width` | 280 px | правая колонка (оглавление) |
| `--panel-width-min` / `--panel-width-max` | 200 px / 480 px | границы ресайза правой колонки |
| `--editor-max-width` | 720 px | ширина текста редактора |
| `--indent-step` / `--indent-max` | 16 px / 6 | отступ вложенности дерева |

### 2.5. Типографика

Шрифты: **Inter** (`--font-sans`, начертания 400–600) и **JetBrains Mono**
(`--font-mono` / `--font-editor`, 400–500). Шрифты лежат локально в
`frontend/public/fonts` и подключаются через `frontend/src/styles/fonts.css` —
приложение не обращается к CDN в рантайме.

Размеры: `--text-xs` 11, `--text-sm` 12, `--text-base` 13, `--text-md` 14,
`--text-lg` 16, `--text-xl` 20, `--text-2xl` 26 px.
Интерлиньяж: `--leading-tight` 1.3, `--leading-normal` 1.55,
`--leading-relaxed` 1.75 (предпросмотр).

### 2.6. Motion и слои

`--duration-fast` 120, `--duration-normal` 180, `--duration-slow` 240 ms;
`--ease-out` — плавное затухание.

Слои: `--z-sticky` 10, `--z-drawer` 30, `--z-overlay` 40, `--z-modal` 50,
`--z-palette` 60.

## 3. Темы

Три состояния: `light`, `dark`, `system`.

- `system` (значение по умолчанию для новых установок) — атрибут `data-theme`
  снимается с `<html>`, тема следует за настройкой операционной системы.
- `light` / `dark` — атрибут `data-theme` выставлен явно и всегда сильнее
  системной темы.
- Тема по умолчанию для существующих пользователей — тёмная; старый ключ
  `localStorage['noto-theme']` читается как fallback.

Тёмная тема — графитовая «Obsidian Slate»: canvas `#09090b`, панель
`#121215`, поверхность `#18181b`, контейнер `#1f1f22`, граница `#27272a`,
акцент `#818cf8`. Светлая — нейтральная: `#fafafa` / `#ffffff` /
`#6366f1`.

### 3.1. Раскладка

Рельса разделов, три колонки и постоянная строка состояния (фазы 6, 7 и 10):

```
┌────┬────────────┬──────────────────────────┬──────────────────┐
│ E  │ левая      │ вкладки → крошки →       │ правая           │
│ S  │ колонка    │ теги → редактор          │ колонка          │
│ F  │ 200…480 px │   (макс. 720 px)         │ 280 px (оглавл.) │
│ H  │  хранилище │                          │  (ресайзится)    │
│ T  │  разделы   │                          │                  │
│ ── │  дерево    │                          │                  │
│ ☾⚙ │  подвал    │                          │                  │
├────┴────────────┴──────────────────────────┴──────────────────┤
│ строка состояния: иконки правой колонки и темы · статус · путь ·│
│ Ln/Col · слова · UTF-8 (24 px)                                │
└────────────────────────────────────────────────────────────────┘
```

- **Рельса** (44 px, фиксированная): иконки разделов `E` explorer, `S` search,
  `F` filters, `H` history, `T` trash; внизу — тема и настройки. Рельса —
  аккордеон: иконка переключает содержимое соседней колонки, открыт ровно один
  раздел. Рельса никогда не исчезает.
- **Левая колонка**: шапка хранилища (имя + путь + новая заметка, новая папка,
  обновить), шапка активного раздела, содержимое раздела, подвал (счётчики и
  импорт/экспорт). Колонка **всегда видна**: сворачивания нет ни кнопкой, ни
  горячей клавишей, ни настройкой; ширина ресайзится (200…480 px).
- **Правая колонка**: оглавление заметки (заголовки Markdown) и панели плагинов.
  Она скрывается кнопкой **постоянной строки состояния** — иначе скрытую колонку
  нельзя вернуть. Ресайзер (`ColumnResizer`) одинаков для обеих колонок; ширина
  правой хранится в настройках (`rightPanelWidth`).
- Вкладки плоские: активная помечена 2 px подчёркиванием акцентом, скруглений
  нет. Высоту полосы вкладок задаёт токен `--tab-height` (40 px) — она равна
  высоте шапок остальных колонок.

### 3.2. Одна линия рамки

Все колонки начинаются с одной высоты, иначе вертикальные разделители начинаются
и заканчиваются на разных `y`, а горизонтальные линии не сходятся (это была
жалоба пользователя в фазе 10).

| Правило | Значение |
|---|---|
| высота шапки | `--header-height` (40 px) — у рельсы, колонки, полосы вкладок и outline |
| фон шапки | `--bg-sidebar` у всех колонок; `--bg-surface` только за рабочей областью |
| линия под шапками | 1 px `--border`, одна на всю ширину |
| вертикальные разделители | 1 px `--border`, непрерывны от верхней до нижней линии |
| нижняя линия | 1 px `--border` по всей ширине (строка состояния) |

Шапка раздела — `.column-header`: она липкая (`position: sticky`), поэтому тело
раздела прокручивается под ней, а шапка остаётся на месте.

## 4. Иконки

Единый реестр — `frontend/src/ui/icons.tsx` (на базе `lucide-preact`).

```tsx
import { Icon } from '../ui/icons';

<Icon name="folder" size={16} />
```

Правила:

- Толщина штриха у всех иконок одинаковая (`1.75`), цвет наследуется
  (`currentColor`).
- Иконка без подписи декоративна: `aria-hidden="true"`. Кнопка с одной
  иконкой обязана иметь `aria-label` **и** `title`.
- Имя иконки, которого нет в реестре, не является ошибкой: показывается
  нейтральная точка. Это позволяет плагину передать произвольную строку.

Имена в реестре (список намеренно короткий: каждый иконка попадает в бандл):

```
archive  bell       bookmark     calendar      chevron-down
chevron-right  chevron-up  chevrons-down-up  chevrons-up-down
circle   clock     command      copy          dots-vertical
file-plus  file-text  filter     folder        folder-open
folder-plus  hash    image      link          menu
moon     more-horizontal  move  network       panel-left
panel-right  pencil  plus       puzzle        refresh-cw
rotate-ccw  search  settings    star         sun
tags      trash      upload     x
```

Чтобы добавить иконку, внесите её в `frontend/src/ui/icons.tsx` — реестр
экспортируется как `ICON_NAMES`, список имён используется в документации и в
тестах.

## 5. Правила для плагинов

Плагин не копирует CSS приложения: он использует те же семантические
токены, которые наследуются в дерево DOM.

```tsx
<div style={{ color: 'var(--fg-muted)', fontSize: 'var(--text-sm)' }}>
```

Что доступно плагину:

- цвета: `--fg`, `--fg-secondary`, `--fg-muted`, `--bg-surface`,
  `--bg-elevated`, `--bg-inset`, `--bg-hover`, `--border`, `--accent`,
  `--accent-subtle`, `--success`, `--warning`, `--danger` и их `-subtle`;
- размеры: `--space-1`…`--space-8`, `--radius-sm/md/lg`, `--text-xs…2xl`,
  `--font-sans`, `--font-mono`;
- состояния: `--focus-ring`, `--selection-bg`.

Классы вкладок и панелей плагинов имеют префикс `.noto-plugin-`, поэтому
не могут конфликтовать с классами приложения.

Поле `icon` в описании элемента панели или панели инструментов — это **имя
иконки** из реестра (например `file-text`). Старые значения остаются рабочими:
неизвестное имя показывается как точка.

## 6. Компоненты: правила

- **Кнопка-иконка** — квадратная, `--touch-target`, `aria-label` + `title`.
  Общий помощник — `frontend/src/ui/tooltip.tsx` (`IconButton`, `tooltipAttrs`):
  имя действия не может разойтись между подписью для assistive technology и
  подсказкой.
- **Иконка вместо текста** — действует там, где действие однозначно: контекстное
  меню дерева, подвал сайдбара, строка состояния, строка корзины. Текст сохраняется
  там, где он несёт смысл (навигация, заголовки секций, палитра команд, диалоги).
- **Дерево** — строка `--row-height`, иконка слева, имя с усечением, действия
  справа; выбранная строка — `--bg-selected`. Вложенность показывают
  направляющие линии (`--indent-step` = 16 px), число заметок в папке — счётчик
  справа (`tabular-nums`, `min-width: 3ch`, показывается только при > 0).
- **Вкладки** — плоские: 32 px, отступ `0 8px`, промежуток 2 px, активная вкладка
  помечена 2 px подчёркиванием акцентом; кнопка закрытия только у активной.
- **Диалог** — `.dialog` на `.dialog-backdrop`, фокус внутри, Escape закрывает,
  клик по подложке закрывает.
- **Палитра** — фильтр, стрелки, Enter, Escape; активный элемент —
  `--bg-selected`.
- **Пустое состояние** — `<EmptyState/>`: иконка, заголовок, пояснение,
  действие.

### 6.1. Где живёт действие, а где — состояние

Правило фазы 7, которое разводит два разных вопроса:

* **Действие хранилища живёт в шапке раздела, к которому оно относится.**
  Поиск, Graph, Archive, палитра команд, менеджер плагинов и создание
  заметки/папки — в шапке EXPLORER и в шапке хранилища.
* **Действие представления живёт рядом с тем, что оно меняет.** Раскрыть все
  папки и схлопнуть все папки — в группе действий EXPLORER, рядом с деревом:
  это действия над видом дерева, а не над хранилищем.
* **Состояние документа живёт в строке состояния.** Статус автосохранения,
  путь, позиция курсора, счётчики, формат и признак «только чтение» — в
  постоянной строке состояния. Она никогда не скрывается, поэтому скрытую
  колонку всегда можно вернуть.
* **Счётчик живёт рядом со своим владельцем.** Счётчик папки — в строке
  дерева; итогов по всему хранилищу в шапке раздела нет.
* **Панель плагина — в правой колонке**, под оглавлением: вспомогательные
  материалы не должны отбирать ширину у редактора.
* **Пункт контекстного меню плагина — в меню того узла, к которому он
  относится**, а не в подвале колонки.

### 6.2. Индикатор связи с бэкендом

Маленькая точка в строке состояния приложения (`ConnectionIndicator`,
`frontend/src/components/ConnectionIndicator.tsx`) — **единственный цветной
элемент оболочки**:

| Состояние | Цвет | Смысл |
| --- | --- | --- |
| `connected` | `--success` | бэкенд отвечает |
| `connecting` | `--warning` | проверка идёт, ответа пока нет |
| `unreachable` | `--danger` | бэкенд не отвечает |

Правила оформления:

- размер 8 px, `flex: none`, без подписи; состояние читается по цвету, а
  подробность — в `title` и в доступном имени;
- при `unreachable` точка — кнопка: клик просит повторить проверку. В
  остальных состояниях она помечена `aria-disabled`, чтобы assistive
  technology не предлагала бесполезное действие;
- потеря связи — это состояние, а не ошибка, поэтому она не показывается
  баннером: баннер остаётся только для настоящих ошибок;
- цвет берётся из токенов (`--success`, `--warning`, `--danger`), а не из
  литералов, поэтому точка следует за темой;
- точка стоит в строке состояния, рядом со статусом автосохранения (фаза 13): в
  шапке эксплорера она спорила с иконками разделов и не вписывалась в цвет.

### 6.3. Блок отбора, чипы тегов и конфликт (фаза 9)

Правила, которые родились из жалобы пользователя на непонятный интерфейс:

- **Одно действие — одна иконка.** Иконка не повторяется в двух местах оболочки:
  корзина живёт в списке, а не в подвале сайдбара; переключатель колонок — в
  строке состояния, а не в подвале сайдбара. Если действие выглядит одинаково
  в двух местах, одно из них лишнее.
- **Подвал колонки — только то, чему нет места выше.** В подвале сайдбара
  остаётся импорт/экспорт; всё, что уже есть в шапке раздела или в строке
  состояния, из подвала убрано.
- **Блок отбора объясняет себя сам.** У блока **Filter** есть видимая строка
  пояснения, а у каждой его части («Tags», «Saved») — подсказка. Блок, смысл
  которого нужно угадывать, — дефект.
- **Фильтр обязан быть виден в результате.** Запрос не только считает совпадения:
  дерево заметок показывает только совпавшие заметки (и папки, где они
  лежат), а рядом с разделом появляется метка «filtered». Кнопка сброса в поле
  возвращает полное дерево.
- **Активный фильтр виден всегда — в строке состояния.** Окно фильтров живёт
  поверх приложения и его закрывают; метка рядом с разделом — мелкая и её легко
  не заметить. Поэтому в постоянной строке состояния стоит чип «Filter: <запрос>»
  со счётчиком совпадений и крестиком, который сбрасывает фильтр и возвращает
  полное дерево. Чип нейтральный: цветной элемент оболочки — только точка
  соединения. Имя кнопки сброса в строке состояния — «Clear the active filter»:
  кнопка сброса в поле окна фильтров называется «Clear the filter», и два
  одинаковых имени сломали бы и поиск по доступным именам, и тесты.
- **Тег — это часть текста.** Полоса тегов над редактором показывает теги
  заметки и умеет их добавлять и убирать, но пишет она в текст: отдельного
  поля у заметки нет, и в зашифрованном хранилище иначе не обойтись.
- **Конфликт сохранения — это диалог, а не строка ошибки.** «Заметку изменили в
  другом месте» — не отказ, а выбор: взять версию сервера, оставить свою или
  скопировать свою. Пока выбор не сделан, автосохранение этой заметки ждёт.

### 6.4. Рельса разделов и колонка (фаза 10, уточнение фазы 11)

Правила, которые родились из жалобы пользователя на «не сходящиеся» колонки и на
дублирующееся меню:

- **Навигация живёт в рельсе, а не в колонке.** Рельса (44 px) перечисляет
  разделы приложения. Рельса — аккордеон: открыт ровно один раздел, и его иконка
  несёт `aria-current="page"`.
- **Под иконкой нет буквы.** Подпись раздела живёт в `aria-label` и в `title`
  кнопки (как в рельсе Obsidian). Буквы под иконками («E», «S», «F»…) читались как
  визуальный мусор: на экране 44 px это пятно цветных пятен, а не подсказка.
- **Порядок разделов — это порядок работы человека.** Сначала заметки
  (`Explorer` → `Calendar` → `Search` → `Filters`), потом жизнь хранилища
  (`History` → `Notifications` → `Trash`). Между группами — тонкий разделитель,
  как в рельсе Obsidian. Список разделов живёт в одном месте
  (`core/commands/appCommands.ts`, `RAIL_SECTIONS`): рельса рисует его, палитра
  перечисляет команды, клавиатура раскладывает по нему сочетания клавиш.
- **Иконка раздела семантична.** `folder` — дерево заметок, `calendar` — дни,
  `search` — поиск, `filter` — отбор, `clock` — история, `bell` — уведомления,
  `trash` — корзина.
- **Пункт раздела — квадрат 28×28 px**, иконка 17 px (компактная навигация Mem).
- **Рельса никогда не исчезает.** У левой колонки нет сворачивания: ни кнопки,
  ни горячей клавиши, ни настройки. На узком экране (≤820 px) колонка уезжает в
  drawer по кнопке «Toggle navigation», а рельса остаётся на месте.
- **Раздел — это шапка и тело.** У каждого раздела своя шапка (`.column-header`,
  40 px, липкая) и своё тело. Шапки всех колонок стоят на одной высоте, иначе
  линии не сойдутся (см. §3.2).
- **У строки дерева одна кнопка.** Действия строки живут в контекстном меню
  («три точки»): Rename, Move, New note, New folder, Duplicate, Delete. Кнопки
  действий прямо в строке продублировали меню и наезжали на него.
- **Правый клик по строке открывает то же меню.** Меню папки показывает её имя и
  пункт «New folder» создаёт папку **внутри** неё.
- **Счётчик отбора живёт там, где живёт запрос.** Число совпадений и кнопка
  очистки — в модуле `Filters` окна поиска, а не в модуле `Search`: в поиске запроса
  нет, и счётчик там только мешал.
- **Имя нового объекта пишет человек.** Диалог создания открывается с пустым
  полем и плейсхолдером («Folder name», «Note name»). Плейсхолдер — не значение:
  папка, названная «New folder», оставалась в крошках навсегда. Диалог с пустым
  именем не закрывается.
- **Нативный вид не рисуется.** Поле выбора файла прячется за своими элементами
  («Choose files», «Choose archive»): нативная кнопка браузера не вписывается в
  рамку поля.

### 6.5. Палитра команд, календарь и уведомления (фаза 11)

- **Палитра — модальное окно.** Затемнение на весь экран, карточка шириной
  `min(620px, 100%)` в верхней трети экрана, список прокручивается внутри
  карточки. Плоский список на всю страницу — не палитра, а выпадашка.
- **У команды есть заголовок и описание.** Они стоят на двух строках (сетка),
  сочетание клавиш — справа. Склеенные в одну строку «New noteCreate a new
  Markdown note» нечитаемы.
- **Календарь показывает дни, а не список.** Сетка месяца начинается с понедельника,
  дни соседних месяцев приглушены. Знаков два: точка под цифрой — «сегодня», заливка
  `--accent-subtle` с акцентной цифрой — «в этом дне есть записи». Заметка принадлежит
  дню своего `createdAt` **и** дню своего `updatedAt`; исключение — дневная заметка:
  её имя и есть дата (`2026-10-29.md`), и она принадлежит только этому дню (фаза 13).
- **Уведомление — типизированная запись.** Вид (`info` / `success` / `warning` /
  `error`), заголовок, необязательное пояснение, время, отметка «прочитано» и
  путь заметки. Список живёт в сторе, рельса показывает счётчик непрочитанных.
- **Календарь и уведомления грузятся лениво**, как и остальные разделы: они не
  должны попадать в entry-чанк. То же и с движком языка запросов (фаза 12): он
  нужен только тогда, когда кто-то задал вопрос, поэтому и парсер, и предикаты
  живут в отдельном чанке.

### 6.6. Комфорт интерфейса: вкладки, теги, избранное, напоминания (фаза 12)

- **Вкладки — карточки, а не линия.** Открытые заметки различаются глазами: зазор
  4 px, скругление сверху, неактивная вкладка — карточка со своим фоном
  (`--bg-inset`) и рамкой, активная вкладка приподнята (фон `--bg-surface`,
  рамка без нижней линии) и сливается с поверхностью редактора. Имя вкладки
  обрезается многоточием. Полоса вкладок остаётся шапкой рабочей области: та же
  высота, тот же фон, та же нижняя линия рамки. Инлайновых стилей в компоненте
  нет — вся форма живёт в `styles/tabs.css`.
- **Полоса тегов — группа, а не набор рамок.** У полосы есть подпись («Tags» с
  иконкой), теги — пилюли с фоном, кнопка «+» — пилюля той же высоты, а поле
  добавления — настоящее поле (18 ch, плейсхолдер «Add a tag…», акцентное кольцо
  фокуса). Высота полосы не меняется, когда поле появляется и исчезает.
- **В календаре два знака, а не один.** Точка под цифрой — «сегодня». День, в
  котором есть записи, получает заливку `--accent-subtle` и цифру акцентным
  цветом. Путать их нельзя: это разные вопросы.
- **Избранное — раздел рельсы.** Иконка `star`, раздел сразу после `Explorer`.
  В меню строки — «Add to favorites» / «Remove from favorites», в дереве — звёздочка
  у избранной заметки. Список живёт в `localStorage`: это список пользователя, а
  не часть хранилища.
- **Напоминание — это момент.** Модель `Reminder` (день, время, текст, путь
  заметки) живёт в `core/reminders` и в `localStorage`. Когда момент приходит,
  приложение пишет запись в список уведомлений **и** показывает системное
  уведомление браузера. Разрешение спрашивается только по действию пользователя:
  браузер не даёт спросить из таймера.
- **Пилюля — это 4 px.** Полностью круглые «таблетки» (`border-radius: 999px`)
  запрещены: скругление задаёт `--radius-md`.

### 6.7. Поиск, фильтры, дни и закрытие вкладки (фаза 13)

- **Поиск и фильтр — один инструмент с двумя модулями.** Лупа и воронка в рельсе
  открывают одно окно поверх приложения: в модуле `Search` — полнотекстовый поиск,
  в модуле `Filters` — язык запросов, чипы тегов, сохранённые фильтры и список
  подходящих заметок. Колонка эксплорера при этом не меняется: дерево остаётся на
  месте, окно живёт поверх. Два раздела колонки с двумя разными полями — это была
  одна функция, разложенная надвое.
- **Знаки разных дней не должны делить цвет.** Точка «сегодня» и заливка «здесь
  есть записи» были оба фиолетовыми: `--accent` и `--accent-subtle`. Точка
  рисуется цветом текста (`--fg`), заливка остаётся акцентной (фаза 13).
- **Дневная заметка принадлежит своему дню.** Имя `2026-10-29.md` — это дата, и
  заметка принадлежит 29-му, а не дню, когда её написали. Обычные заметки ведут
  себя как раньше: день создания и день изменения.
- **Закрытая вкладка закрывает заметку.** Закрытие последней вкладки очищает
  редактор: имя последней заметки не должно висеть в крошках как будто вкладка
  ещё открыта.
