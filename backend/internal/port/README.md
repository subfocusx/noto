# Пакет `port`

## Назначение

Единственный интерфейс доступа к хранилищу: `port.Store`. Через него доменный
слой работает с заметками, поиском, вложениями и корзиной, ничего не зная о
SQLite. Это **замороженный контракт**: изменение интерфейса требует
одновременного изменения реализации, набора конформанс-тестов и документации.

## Публичные типы и функции

| Имя | Что это |
|---|---|
| `Store` | Интерфейс хранилища: узлы дерева, заметки, поиск, вложения, корзина, переиндексация, метаданные. |

Реализации: `internal/sqlitestore` (SQLite) и `internal/testutil.MemStore`
(в памяти, для тестов). Есть ещё заглушка `internal/sealed.NewBlockedStore`,
которая отвечает `vault_sealed`.

## Что нельзя импортировать отсюда

* `port` — лист графа: пакет не импортирует ничего из `backend/internal`;
* `port` не импортирует `internal/sqlitestore` (и наоборот): реализация
  подставляется снаружи, в `cmd/noto`;
* новые методы `Store` не добавляются «на будущее»: каждый новый метод
  обязан иметь реализацию в обеих реализациях и кейс в наборе
  конформанс-тестов.

## Проверка

`go test ./internal/port` (набор конформанс-тестов `porttest` требует
нулевого числа расхождений между реализациями).
