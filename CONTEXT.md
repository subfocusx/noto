# CONTEXT.md — словарь домена Noto

Этот файл — словарь проекта. Он отвечает на вопрос «как правильно назвать
вещь в этом репозитории». Одна и та же сущность должна называться одинаково
в коде, в API, в документации и в сообщениях коммитов: иначе через полгода
никто не поймёт, где «заметка», а где «документ».

Правило простое: **если термин есть в этом словаре — используй его; если
словарь молчит — добавь термин сюда в том же изменении.**

Каждая статья состоит из двух частей:

* **определение** — что это такое в Noto;
* **Avoid:** — синонимы, которые запрещены в этом репозитории (в коде, в
  документации, в именах API). Если вам нужен один из них — это признак
  того, что вы говорите не о том понятии.

Термины оставлены в английском в скобках — так они называются в коде и в
API.

---

## 1. Заметка (Note)

**Определение.** Один файл Markdown (`.md`) в каталоге заметок, с уникальным
путём относительно корня хранилища. У заметки есть путь (`path`), имя файла
(`name`), содержимое (`content`), ревизия (`revision`, счётчик оптимистической
блокировки) и метаданные (теги, производные свойства, время изменения).
Заметка — это то, что пользователь видит в дереве и редакторе.

**Avoid:** Memo, Doc, Document, Page, Record, Entry, File (файл — это артефакт
на диске, заметка — это сущность предметной области), Item, Post, Article.

## 2. Папка (Folder)

**Определение.** Каталог внутри дерева заметок. Папка не хранит данных сама:
она группирует заметки. У папки есть путь и имя; корнем дерева считается
каталог заметок. Папка может быть переименована, перемещена и удалена
(удаление — это перенос в корзину).

**Avoid:** Directory (каталог на диске), Dir, Tree (дерево — это структура
целиком), Category, Collection, Group, Album, Namespace, Folder Node.

## 3. Дерево (Tree)

**Определение.** Иерархия папок и заметок, которую показывает левая колонка.
Дерево строится на сервере (`GET /api/tree`) из файлов на диске; в базе
хранятся только метаданные. Дерево — это **представление** (view), а не
отдельная сущность.

**Avoid:** Hierarchy (общее слово вне домена), Directory Tree, Folder Tree,
Navigator, Sidebar (это компонент интерфейса, а не структура), File Tree.

## 4. Тег (Tag)

**Определение.** Слово, начинающееся с `#` в тексте заметки (`#work`,
`#idea/2026`). Теги вычисляются из текста заметки, приводятся к нижнему
регистру, сохраняют порядок появления и не повторяются. Тег — это
**производное свойство**, а не отдельная запись в базе: удаление `#work` из
текста удаляет тег.

**Avoid:** Label, Keyword, Category, Hashtag (в коде и в API — только `tag`),
Topic, Taxonomy, Tag List.

## 5. Свойства заметки (Note Properties)

**Определение.** Производные значения, которые вычисляются из текста и пути
заметки: `title`, `tag`, `has_task_list`, `has_incomplete_tasks`, `has_code`,
`has_image`, `has_link`, `has_attachments`. Свойства — это **кэш**, а не
источник истины: источник истины — файл `.md`; свойства пересчитываются при
сохранении заметки и при перестроении индекса. Если пересчёт не удался,
свойства помечаются как устаревшие (`stale`).

**Avoid:** Metadata (в этом проекте так называют строку в SQLite — это разные
вещи), Derived Fields, Attributes, Facets, Computed Columns, Extra Info.

## 6. Плагин (Plugin)

**Определение.** Встроенный в приложение модуль с дополнительным
поведением: панель, пункт меню, команда палитры, подписка на события. Плагины
Noto — это доверенный код, собранный вместе с приложением; установки плагинов
из сети или с диска нет, песочницы нет. Плагин объявляет манифест с
разрешениями (`permissions`) и минимальной версией API.

**Avoid:** Extension, Add-on, Module (в проекте «модуль» — это пакет Go),
Theme, Script, Macro, Integration.

## 7. Контракт плагинов (Plugin Contract)

**Определение.** Публичный интерфейс платформы: типы и версия
`PLUGIN_API_VERSION` в `frontend/src/plugins/contract.ts`. Это единственное,
что может импортировать встроенный плагин из `src/plugins/**`. Версия
контракта семантическая: расширение — минорная версия, несовместимое
изменение — мажорная.

**Avoid:** Plugin API (то же самое по смыслу, но в коде — `contract.ts` и
`PLUGIN_API_VERSION`), SDK, Plugin Interface, Plugin SDK, Host API.

## 8. Хранилище (Vault)

**Определение.** Каталог на машине пользователя, в котором живут данные
Noto: заметки, вложения, корзина и скрытая папка `.noto` с базой данных. В
хранилище нет учётных записей и паролей: доступ защищают средства уровня
ОС/VPN. Хранилище можно сменить в настройках.

**Avoid:** Storage (в этом проекте так называют техническое хранилище
SQLite), Library, Workspace, Space, Container, Volume, Folder (папка внутри
дерева), Repository, Collection.

## 9. Запечатанное хранилище (Sealed Vault)

**Определение.** Режим хранения, в котором данные шифруются **в браузере**
(Argon2id + AES-256-GCM) и сервер становится слепым хранилищем объектов:
он видит байты и идентификаторы, но не ключи. В этом режиме сервер
отказывает открытые эндпоинты с кодом `vault_sealed`. Ключ живёт только в
памяти вкладки и никогда не попадает в плагин.

**Avoid:** Encrypted Storage (то же по смыслу), Encryption, Encrypted
Storage Mode, Locked Vault, Crypto Vault, Password-Protected Storage, Secure
Mode.

## 10. Запрос (Query)

**Определение.** Выражение на языке запросов Noto, которое отвечает на
вопрос «какие заметки подходят?». Язык описан в `docs/QUERY_LANGUAGE.md`:
операторы `==`, `!=`, `>`, `in`, `contains`, `startsWith`, `endsWith`, поля
(`path`, `name`, `title`, `tag`, `folder`, `content`, `created_at`,
`updated_at`, `has_*`) и относительное время (`now - 7d`). Запрос
разбирается в общее промежуточное представление (IR), которое либо
компилируется в SQL (открытый режим), либо в предикат по памяти (запечатанный
режим).

**Avoid:** Search (поиск — это полнотекстовый поиск по FTS5, другой механизм),
Filter (в UI — это конкретный экран фильтра, но в API это `query`), Query
String, Expression, Where, Criteria, Matcher, Statement, Predicate.

## 11. Представление (View)

**Определение.** Сохранённый именованный фильтр: запрос + иконка + порядок
сортировки. Представления живут в настройках приложения, перечисляются в
интерфейсе и открывают список заметок, отобранных запросом. Представление —
это ссылка на запрос, а не копия правил.

**Avoid:** Saved Search (то же по смыслу), Preset, Query Preset, Bookmark,
Smart Folder, Filter, Saved Filter, Query, Shortcut, Saved Query.

## 12. Индекс поиска (Search Index)

**Определение.** Индекс FTS5 в базе SQLite, который хранит путь, имя и тело
заметки и позволяет искать по тексту с ранжированием и фрагментом. Индекс —
производная от файлов: он перестраивается командой переиндексации, а при
отсутствии FTS5 поиск падает на `LIKE`-сканирование с предупреждением.

**Avoid:** Search, FTS, Index (индекс — безличное; уточняйте), Full-Text
Index, Vector Index, Embeddings, Search Engine, Lucene, Elasticsearch.

## 13. Корзина (Trash)

**Определение.** Каталог, куда переносится удалённая заметка или папка.
Удаление — это перенос, а не стирание, поэтому удалённое можно восстановить.
Корзина принадлежит хранилищу и переживает перезапуск.

**Avoid:** Recycle Bin, Bin, Deleted Items, Recently Deleted, Archive (в UI
кнопка «Архив» — это другое), Soft Delete, Tombstone.

## 14. Вложение (Attachment)

**Определение.** Файл, который лежит рядом с заметками в каталоге вложений и
относится к заметке: изображение, PDF, текстовый файл. Сервер определяет тип
по содержимому, а не по расширению, и не отдаёт файл с опасным типом.

**Avoid:** Asset, File (файл — общий термин), Media, Upload, Resource, Blob,
Binary, Image (изображение — один из видов вложения).

## 15. Черновик (Draft)

**Определение.** Несохранённая версия текста заметки, которую редактор
хранит в IndexedDB, чтобы не потерять изменения при сбое сети или
перезагрузке. Черновик живёт на клиенте, пока заметка не сохранена.

**Avoid:** Buffer, Undo (отмена — другое), Autosave State, Temp Save,
Autosave (автосохранение — механизм, черновик — его результат), Local Copy.

## 16. Редактор (Editor)

**Определение.** Компонент CodeMirror 6, в котором пользователь правит текст
заметки. Редактор отдаёт изменения с задержкой (800 мс), умеет вставлять
текст по позиции и не умеет молча переписывать весь документ (в контракте
плагинов нет `setText`).

**Avoid:** Textarea, Input, Code Area, Markdown Editor (в интерфейсе окно
редактора — это редактор), CodeMirror (это реализация, а не понятие),
Monaco, Ace.

## 17. Рендер markdown (Markdown Render)

**Определение.** Превращение текста заметки в безопасный HTML для показа:
`marked` строит дерево, `DOMPurify` его чистит. Сырой HTML из заметки не
попадает в страницу никогда.

**Avoid:** Preview (в интерфейсе режим предпросмотра удалён в фазе 6),
Rendering, Rendering Engine, Sanitizer (очиститель — часть рендера),
Formatter, Markdown Processor, Html, InnerHTML (это способ вставки, а не
понятие).
