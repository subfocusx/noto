# Пакет `vault`

## Назначение

Хранилище (vault) на машине пользователя: где оно находится, как выглядит
его внутренняя раскладка (`.noto` с базой, заметки, вложения, корзина), файл
конфигурации пути, проверка каталога и обзор содержимого (для выбора папки в
настройках).

## Публичные типы и функции

| Имя | Что это |
|---|---|
| `Config` | Записанная конфигурация хранилища (путь). |
| `Layout` | Раскладка хранилища: корни заметок, вложений, корзины и базы. |
| `ConfigFile()` | Путь файла конфигурации. |
| `Read()` | Читает конфигурацию (второй результат — «настроено ли»). |
| `Write(path)` | Записывает конфигурацию. |
| `Clear()` | Убирает конфигурацию. |
| `Validate(path)` | Проверяет, что каталог пригоден для хранилища. |
| `Resolve(path)` | Вычисляет раскладку по корню. |
| `ApplyTo(cfg, path)` | Переносит конфигурацию приложения на новое хранилище. |
| `Browse(path)` | Обзор каталога (для выбора папки). |
| `BrowseResult` / `Dir` | Результат обзора: каталоги и файлы. |
| `Root()` | Корневой каталог приложения (где лежит файл конфигурации). |

## Что нельзя импортировать отсюда

* `vault` не импортируется из `internal/notes` и `internal/sqlitestore` — он
  работает с путями, а не с заметками;
* `vault` не импортируется из `internal/api`: выбор хранилища — это команда
  и настройка, а не HTTP-эндпоинт в домене;
* внутренние детали (`checkWritable`, `parentOf`) не экспортируются.
