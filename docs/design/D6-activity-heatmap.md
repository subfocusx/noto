# D6 — Тепловая карта активности

**Status:** Draft

**Связанные документы:** `docs/PLUGIN_API.md`, `docs/QUERY_LANGUAGE.md`
(поля `created_at`, `updated_at`), `frontend/src/plugins/builtin/`.

---

## Context

В Noto есть время заметки (`created_at`, `updated_at`) и есть полнотекстовый
поиск — но нет ни одного способа **увидеть** свою активность. Проблема
известная: библиотека растёт, а «что я вообще делал в марте» по списку
файлов не ответишь.

Тепловая карта активности (heatmap) — это сетка «день × неделя/месяц», где
интенсивность цвета означает количество изменений. Идея пришла из GitHub
(`github.com` contribution graph) и из `usememos/memos` (MIT), где heatmap
есть плагином.

Почему это **плагин**, а не встроенная функция:

* это не заметка, не дерево и не поиск — это отдельная визуализация;
* приложение уже имеет платформу плагинов, и карта активности идеально в
  неё укладывается: панель + настройки + своё состояние;
* плагин — честный способ проверить, что платформа (D-волна 6) действительно
  позволяет делать полезные вещи, а не только считать слова.

Ограничения:

* данные для карты — это `modTime` заметок: отдельной таблицы активности
  нет, и вводить её не хочется;
* в запечатанном режиме сервер не видит заметок — карта должна считаться
  в браузере по тому, что уже расшифровано.

## Decision

1. **Тепловая карта — плагин** (`frontend/src/plugins/builtin/activity`),
   а не встроенный экран. Плагин использует только публичный контракт
   (`src/plugins/contract.ts`) — это проверяется `npm run check:boundaries`
   (правила R3, R7).

2. **Данные — время изменения заметок (`modTime`/`updated_at`),** а не
   отдельный журнал действий. Отдельного журнала нет и не будет: он стоил бы
   записи на каждое событие, а выигрыш неочевиден.

3. **Считает карта то, что видит:** в открытом режиме — по данным API, в
   запечатанном — по расшифрованному дереву в памяти. Плагин получает снимок
   заметок через контракт и строит сетку сам, не прося сервер считать
   агрегаты.

4. **Шкала заранее определена:** последние 52 недели, один квадрат — один
   день, пять уровней интенсивности (0…4), где 0 — «нет изменений». Максимум
   считается по самому плотному дню, а не от «среднего».

5. **Нажатие на квадрат — это запрос.** Клик по дню открывает список заметок
   этого дня через тот же язык запросов (`updated_at` в границах дня), то
   есть карта не заводит собственного механизма фильтрации.

6. **Настройки плагина:** период (52 или 26 недель), показывать ли подписи
   месяцев, показывать ли тултип с числом изменений. Настройки живут в
   `noto-plugins` (как у всех плагинов), а не в настройках приложения.

7. **Карта не меняет данные.** Она ничего не пишет в заметки и не создаёт
   индексов; это чистое чтение.

## Consequences

**Возможности:**

* пользователь видит свою активность без нового хранилища и без нового
  серверного контракта;
* карта проверяет платформу на полезном сценарии: контракт должен
  позволять получить список заметок с их временем;
* клик по дню ведёт в обычный список заметок — никакой отдельной
  «истории активности».

**Издержки и обязанности:**

* данные — это `updated_at`, то есть «последнее изменение», а не «сколько
  раз меняли»: интенсивность дня меряется числом заметок, а не числом
  правок. Это осознанное упрощение, его надо назвать в интерфейсе;
* при большом числе заметок передача снимка для расчёта может быть дорогой:
  нужен либо пагинационный API, либо расчёт на сервере (отдельное решение);
* в запечатанном режиме карта считается по расшифрованному дереву, то есть
  только пока хранилище открыто.

**Открытые вопросы (до реализации):**

* брать ли снимок всех заметок или считать агрегат на сервере в открытом
  режиме (это быстрее, но добавляет эндпоинт и различие между режимами);
* нужен ли отдельный эндпоинт для агрегата, если снимок окажется дорогим;
* как карта выглядит в мобильном вьюпорте (52 недели не влезают).

## Alternatives considered

| Вариант | Почему отвергнут |
|---|---|
| Встроенный экран, а не плагин | Карта — это отдельная визуализация, а не часть дерева или поиска. Встроенный экран расширяет «ядро» интерфейса навсегда; плагин показывает, что платформа годна для такой функциональности. |
| Считать по журналу действий (каждый save — запись) | Требует писать журнал на каждое изменение, хранить и чистить его. Данных больше, а ответ тот же («какие дни были активными»). |
| Отдельные счётчики активности в базе | Та же цена, что и журнал, плюс миграция схемы SQLite. |
| Считать активность только по открытым заметкам (не по сохранённым) | Тогда карта отражает чтение, а не работу. Пользователь ждёт «когда я писал». |
| Показывать активность по дням, а не по квадратам недель | Теряется сравнение «неделя к неделе» — вся ценность графика. |
| Нажатие открывает специальный отчёт | Появляется второй механизм фильтрации. Клик по дню — это запрос, поэтому он ведёт в обычный список заметок. |
| Карта как часть дерева заметок | Дерево показывает структуру, карта — время. Смешивать их значит усложнить оба. |
