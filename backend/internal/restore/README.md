# Пакет `restore`

## Назначение

Логика восстановления из архива бэкапа: проверка структуры и сумм, отчёт о
том, что будет восстановлено, «сухой» прогон (`-dry-run`), отказ при
непустом каталоге без `-force`, атомарная замена базы с сохранением прежней
копии (`noto.db.pre-restore-<ts>`) и откат при ошибке.

## Публичные типы и функции

| Имя | Что это |
|---|---|
| `Options` | Параметры восстановления: путь архива, каталог данных, dry-run, force. |
| `Run(ctx, cfg, opts)` | Выполняет восстановление и возвращает отчёт. |
| `Report` | Отчёт: что восстановлено, что пропущено, что не сошлось. |
| `Group` | Группа файлов отчёта (по назначению: заметки, вложения, база). |
| `PrintReport(w, rep)` | Печатает отчёт в human-читаемом виде. |

## Что нельзя импортировать отсюда

* `restore` не импортируется из `internal/api` и `internal/notes` — только
  из `cmd/restore` и подкоманды `noto restore`;
* формат архива не меняется здесь: он принадлежит `internal/backuppkg`;
* `runRestore`, `checkStructure`, `buildReport`, `undoPlan` — внутренние
  детали, наружу не выставляются.
