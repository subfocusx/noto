# API-CHANGELOG — журнал изменений API Noto

Этот файл — журнал изменений **HTTP API** и **плагинного API** Noto. Он
отвечает на вопрос «что изменилось в контракте и когда».

Соседние документы:

* [`CONTRACT.md`](CONTRACT.md) — **источник истины** по текущему состоянию
  API (маршруты, коды ошибок, правила);
* [`API.md`](API.md) — подробное описание эндпоинтов;
* [`PLUGIN_API.md`](PLUGIN_API.md) — подробное описание плагинного контракта;
* [`design/`](design/) — карточки решений, которые порождают изменения.

---

## 1. Правило версионирования

Версионирование — **семантическое** (semver: `MAJOR.MINOR.PATCH`).

| Часть | Когда растёт |
|---|---|
| `MAJOR` | несовместимое изменение: удалён или переименован эндпоинт, изменён смысл существующего поля, изменён код ошибки, удалён элемент плагинного контракта |
| `MINOR` | обратно совместимое расширение: новый эндпоинт, новое необязательное поле ответа, новая функция в `ctx.api`, новая точка вклада |
| `PATCH` | исправление без изменения контракта: опечатка в описании, уточнение текста, починка поведения внутри заявленного |

### Два контракта, одно расписание

В фазе 8 HTTP API и плагинный API выпускаются **вместе**, под одним
номером релиза: пользователь получает эндпоинт и плагинную функцию, которые
решают одну задачу (например, «запрос» и `ctx.api.query`).

Текущее состояние на момент начала фазы 8:

| Поверхность | Версия контракта | Где объявлена |
|---|---|---|
| Плагинный API | **1.1.0** | `PLUGIN_API_VERSION` в `frontend/src/plugins/contract.ts` |
| HTTP API | **номер контракта не объявлен** — HTTP API документирован в `docs/CONTRACT.md` без версии; `api.Version` ("0.1.0", отдаётся в `GET /api/health`) — это версия сборки пакета, а не версия контракта | `backend/internal/api/api.go` |

Первая запись журнала (1.2.0) вводит общий номер релиза для обеих
поверхностей.

### Обязательное правило записи

Каждое изменение контракта **обязано** появиться здесь в том же изменении,
что и сам код. Запись без даты и без указания, что именно изменилось,
недопустима.

Формат записи:

```
### <версия> (<фаза>) — <Статус>
- **Added / Changed / Fixed / Removed / Deprecated** — что именно, с указанием
  эндпоинта, поля или функции плагина.
```

Статусы записей: `Released` (изменение в репозитории и проверено) и
`Planned` (решение принято, код ещё не написан).

### Что не требует новой версии

* исправление текста описания, опечатка, уточнение формулировки;
* исправление поведения, которое не соответствует уже описанному контракту
  (это **ошибка**, а не изменение: версия не растёт, но запись в журнале
  делается в `Fixed`);
* новые внутренние поля, которые сервер не отдаёт клиенту.

## 2. Журнал

### 1.2.0 (phase 8) — Released

- **Added** — `POST /api/query`: выполнение запроса на языке запросов Noto
  (см. [`design/D1-query-language.md`](design/D1-query-language.md) и
  [`QUERY_LANGUAGE.md`](QUERY_LANGUAGE.md)). Тело: `{"query": "...",
  "limit": ...}`; ответ: `{"hits": [...], "total": N, "partial": false}`.
- **Added** — `GET /api/tags`: список тегов хранилища со счётчиками заметок
  (основа для дерева тегов и для автодополнения).
- **Added** — плагинный API 1.2.0: `ctx.api.query(query, limit?)` и
  `ctx.api.tags()`, за новым разрешением `query.read`.
- **Changed** — `PLUGIN_API_VERSION` поднимается с `1.1.0` до `1.2.0`; плагины
  с `minApiVersion: "1.0.0"` и `"1.1.0"` продолжают работать (изменение
  аддитивное: новые члены контракта необязательны в типе).
- **Fixed** — сравнение моментов времени в SQL-компиляторе языка запросов
  шло в секундах, а колонки базы хранят миллисекунды; теперь обе
  реализации языка дают одинаковый ответ (проверено тестом паритета).

### 1.1.0 (phase 7) — Released

- **Added** — плагинный API 1.1.0: необязательное состояние хранилища
  `ctx.vault` (`mode`, `encrypted`, `locked`, `formatVersion`). Ключевой
  материал плагинам недоступен (границы R11 и R12).

### 1.0.0 (phase 2) — Released

- **Added** — плагинный API 1.0.0: контракт, манифест, восемь разрешений, девять
  событий, шесть точек вклада, `ctx.api`, `ctx.editor`, настройки плагинов.
- **Added** — HTTP API: базовый набор эндпоинтов, зафиксированный в
  [`CONTRACT.md`](CONTRACT.md) (отдельный номер версии контракта тогда не
  объявлялся).

> Записи 1.0.0 и 1.1.0 приведены в соответствие с состоянием репозитория
> (плагинный API 1.0.0 — фаза 2, 1.1.0 — фаза 7). Номер версии HTTP API до
> фазы 8 отдельно не объявлялся, поэтому в записи 1.0.0 указан только
> плагинный API и появление базового набора эндпоинтов.

## 3. Как читать журнал и что делать при изменении

1. Найдите последнюю запись релиза.
2. Определите, что изменилось: `Added` → минорная версия, `Changed`/`Removed`
   → мажорная, `Fixed` → патч.
3. Внесите запись в этот файл **в том же изменении**, что и код.
4. Синхронизируйте `docs/CONTRACT.md` (или `docs/PLUGIN_API.md`) — журнал
   говорит, **что** изменилось; контракт говорит, **как это выглядит
   сейчас**.
5. Проверьте, что тесты контракта обновлены: `contract_test.go` для HTTP,
   тесты плагинного API для `ctx.api`.
